# SCAUTDOM

Scout-first, Russian, static recruitment website. Existing public routes remain `/`, `/scout.html`, `/model.html`, and `/payments.html`; privacy and 404 pages are included. The model conditions page is primarily a reference for scouts, with a secondary self-application flow.

## Source and delivery

HTML is generated by `python scripts/build-pages.py`. Shared styles and client logic are in `assets/`. No dependencies or framework build are needed for the existing GitHub/Vercel deployment. `python scripts/build-preview.py` mirrors the exact public files into `dist` for the linked Sites publication. The `.openai/hosting.json` file retains the identity of that publication.

The editorial design uses ink, chartreuse and off-white, two clearly captioned AI photo illustrations (`assets/portrait.svg`, `assets/conversation.svg`), and the self-hosted Onest variable font. Each SVG contains a compressed WebP photograph; neither photograph is presented as staff or a success story. Font licensing is preserved in `assets/Onest-OFL.txt`. Text assets allow an atomic commit through GitHub’s tree API.

## Conversion path

The homepage contains the full programme in six ordered chapters: scout role → model conditions → workflow → rewards → questions → scout application. Essential conditions stay visible in the document. The header identifies the current chapter and shows reading progress; each chapter ends with a named next destination. There is no early application button or sticky contact shortcut. Reading is encouraged without unreliable scroll or time gates.

The existing three-step Telegram form is preserved at `/#apply`: visitors choose a source of adult candidates, enter a name and concrete plan, confirm adulthood and understanding of the programme, then review a message before opening Telegram. `/scout.html#apply` remains a contextual bridge to the payout conditions. The model conditions reference page retains a secondary adult self-application flow after the complete conditions.

The site does not submit applications to a server. The visitor must send the draft in Telegram to `@scauttdom`, preserved from the production website. A copy fallback is available. Do not describe the Telegram click as a received or qualified lead. Adult self-declaration is not identity verification; actual onboarding verifies adulthood independently.

Form values are not persisted in cookies or browser storage. Campaign slugs are allowlisted (`utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `ref`), carried through internal links and included in the visible draft. Never put personal information in these tags.

`scautdom:event` and the local `dataLayer` expose `application_started`, `message_prepared`, `telegram_handoff`, and `calculator_used`, with role and step only. No reporting collector is connected. The historical Meta Pixel ID is preserved in config but the advertising script is not loaded. Do not send form answers or adult-category personal data to advertising platforms.

## Financial accuracy

The scout calculator models $1,000 per completed month for three months, for 1–10 models that all complete the programme. It does not forecast results, handle partial cohorts or include VIP. Early departure and advance offsets are explicitly described beside the calculator and on the payments page. Original programme terms and VIP levels are retained. Earnings ranges without supporting evidence are not presented as guaranteed outcomes.

## Progressive enhancement

CSS scroll timelines animate reading progress with a JavaScript fallback. Supported browsers use native cross-document view transitions and scroll-triggered decorative image/bar motion. Unsupported browsers retain the complete static design. Reduced-motion preferences disable decorative motion; no essential text relies on animation. An expand-all control makes the FAQ readable as one continuous section.

## Validation

Run `node --check assets/site.js` and `node --check assets/lead-core.js`. Check HTML routes, unique IDs, internal fragments and all local assets. The pure `ScautdomLead` module is also CommonJS-compatible for checks of payout arithmetic, adult gating, readiness and Telegram encoding. Rebuild `dist` after source edits. Keep the approved Telegram target, programme terms and operational claims grounded in actual records.
